## User Flow

1. Vendor receives email with unique token URL
2. Clicks link → navigates to `/vendor/{token}`
3. VendorPortal component loads:
   - Shows loading spinner
   - Fetches vendor request from API
   - Updates status to "opened" on first view (backend)
4. On success → displays VendorDashboard:
   - Property information
   - Vendor details
   - Current status
   - Token expiration warning
   - Scheduled/completed information (if applicable)
5. On error → shows friendly error message with retry option

## Security Considerations

- **Token-based Access:** 64-character hexadecimal tokens
- **Public Endpoint:** No authentication required (by design)
- **Rate Limiting:** Handled by backend (VendorPortalController)
- **Token Expiration:** Visual countdown display
- **Read-only View:** No modification capabilities in this phase
