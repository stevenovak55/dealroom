## Email Flow

### Scheduling Confirmation Flow
```
1. Vendor submits scheduling form via vendor portal
2. VendorPortalController validates and updates vendor request
3. Status changes to 'scheduled'
4. VendorService->sendSchedulingConfirmation() is called
5. Transaction details retrieved from database
6. ICS calendar file generated
7. Email template rendered with data
8. Email sent via wp_mail()
9. Success/failure logged
```

### Completion Confirmation Flow
```
1. Vendor submits completion form with notes/documents
2. VendorPortalController validates and updates vendor request
3. Status changes to 'completed'
4. VendorService->sendCompletionConfirmation() is called
5. Transaction details retrieved from database
6. Email template rendered with data
7. Email sent via wp_mail()
8. Success/failure logged
```

### Reminder Flow (Optional)
```
1. Cron job calls VendorService->sendDueReminders() daily
2. Query finds all scheduled requests for tomorrow
3. For each request:
   - sendAppointmentReminder() called
   - Email sent
   - reminder_sent flag updated
4. Batch results logged
```

## Database Considerations

### Required Column (Optional for Reminders)
If implementing automated reminders, add to `ma_deal_vendor_requests` table:
```sql
ALTER TABLE wp_ma_deal_vendor_requests 
ADD COLUMN reminder_sent TINYINT(1) DEFAULT 0 AFTER scheduled_time;
```

This column tracks whether a reminder has been sent to prevent duplicates.
