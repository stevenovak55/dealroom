### 1. Database Infrastructure

**Migration 019: `019_create_job_queue_table.sql`**
- Complete job queue table with 15 columns
- 6 optimized indexes for performance:
  - `idx_status` - Status filtering
  - `idx_priority` - Priority ordering
  - `idx_scheduled` - Scheduled job processing
  - `idx_job_type` - Job type filtering
  - `idx_processing` - Primary processing index
  - `idx_stale_jobs` - Stale job detection
  - `idx_cleanup` - Cleanup operations
- Support for 3 priority levels: high, normal, low
- Support for 5 job statuses: pending, processing, completed, failed, dead
- UTF-8mb4 charset with Unicode collation

**Table Structure:**
```sql
CREATE TABLE `wp_ma_deal_job_queue` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `job_name` VARCHAR(255) NOT NULL,
  `job_type` VARCHAR(100) NOT NULL,
  `priority` ENUM('high', 'normal', 'low') DEFAULT 'normal',
  `payload` LONGTEXT NOT NULL,
  `status` ENUM('pending', 'processing', 'completed', 'failed', 'dead') DEFAULT 'pending',
  `attempts` INT UNSIGNED DEFAULT 0,
  `max_attempts` INT UNSIGNED DEFAULT 3,
  `scheduled_for` DATETIME NOT NULL,
  `started_at` DATETIME NULL,
  `completed_at` DATETIME NULL,
  `failed_at` DATETIME NULL,
  `error_message` TEXT NULL,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_processing` (`status`, `priority`, `scheduled_for`)
);
```

## Technical Decisions

### 1. Database-Backed Queue
**Decision:** Use MySQL for job storage instead of Redis/external services
**Rationale:**
- No additional dependencies
- Consistent with existing NotificationQueueService
- WordPress database already available
- Simplifies deployment

### 2. Priority-Based Processing
**Decision:** Use FIELD() for priority ordering
**Rationale:**
- Native MySQL feature
- Efficient for small priority sets
- Clear, readable query logic
- Better than numeric priorities

### 3. CLI-Based Processing
**Decision:** Create standalone PHP script instead of WP-Cron
**Rationale:**
- WP-Cron reliability issues
- Better control over execution
- Easier cron job configuration
- Proper exit codes for monitoring

### 4. JobInterface Design
**Decision:** Comprehensive interface with retry logic
**Rationale:**
- Job-specific retry decisions
- Flexible exponential backoff
- Clear contract for implementations
- Supports varied job types

### 5. Status Management
**Decision:** 5 distinct statuses (pending, processing, completed, failed, dead)
**Rationale:**
- Clear job lifecycle
- Dead letter queue support
- Easy monitoring
- Prevents infinite retries

## Usage Examples

### 1. Register Job Handler
```php
$service = Plugin::instance()->container()->get('job_queue_service');
$service->registerHandler('email.send', ExampleEmailJob::class);
```

### 2. Dispatch Job
```php
$job = new ExampleEmailJob(
    'user@example.com',
    'Transaction Update',
    $email_content,
    'high'
);

$job_id = $service->dispatch($job);
```

### 3. Schedule Future Job
```php
$scheduled_time = date('Y-m-d H:i:s', strtotime('+1 hour'));
$job_id = $service->dispatch($job, $scheduled_time);
```

### 4. Process Queue
```bash
# Via cron (every 5 minutes)
*/5 * * * * docker exec ma-dealroom-wp php /var/www/html/process-queue.php

# Manually
php process-queue.php 50
```

### 5. Get Queue Statistics
```php
$stats = $service->getStats();
// Returns: ['total' => 100, 'pending' => 10, 'processing' => 2, ...]
```

### 6. Retry Failed Jobs
```php
$failed_jobs = $service->getFailed(10);
foreach ($failed_jobs as $job) {
    $service->retryJob($job['id']);
}
```

### 7. Cleanup Old Jobs
```php
// Remove completed jobs older than 7 days
$deleted = $service->cleanupCompleted(7);

// Remove failed jobs older than 30 days
$deleted = $service->cleanupFailed(30);
```
