## What Was Fixed in V2.0.0

### Critical Issue: Cache Not Invalidating

**Problem**:
- Creating new transactions → Not appearing in dashboard
- Deleting transactions → Still showing in list
- Updating records → Changes not reflected immediately
- Stale data persisted for 5+ minutes

**Root Causes Identified**:
1. **Backend**: BaseRepository cache invalidation silently failing when cache service unavailable
2. **Frontend**: React Query staleTime set to 5 minutes, preventing immediate refetch

**Solutions Implemented**:
1. **Backend Fix**: Added WordPress transient fallback in BaseRepository
   - File: `src/Repositories/BaseRepository.php`
   - Method: `invalidateCache()`
   - Now clears cache even if cache service is unavailable

2. **Frontend Fix**: Changed React Query configuration
   - File: `assets/admin/src/App.tsx`
   - Changed: `staleTime: 5 * 60 * 1000` → `staleTime: 0`
   - Now refetches immediately after mutations

**Result**: ✅ Real-time updates working perfectly

### Additional Fixes

**Transaction Model Properties**:
- Added 15 missing database properties (mls_number, bedrooms, bathrooms, etc.)
- File: `src/Models/Transaction.php`
- Impact: API now returns all database fields correctly

**MLS Number Constraint**:
- Fixed duplicate key error for empty MLS numbers
- Solution: Convert empty strings to NULL
- File: `src/REST/Controllers/TransactionController.php`
- Impact: Can create unlimited transactions with or without MLS numbers

## Key Takeaways

### What Went Wrong (V1.x)
1. **Over-reliance on cache service**: Only used cache service, no fallback
2. **Aggressive frontend caching**: 5-minute staleTime prevented real-time updates
3. **Incomplete model mapping**: Missing properties caused data loss
4. **Strict constraints**: Didn't account for NULL values

### What We Fixed (V2.0.0)
1. **Dual-layer cache clearing**: Cache service + WordPress transient fallback
2. **Zero staleTime**: Immediate refetch after mutations
3. **Complete model**: All database fields mapped
4. **Flexible constraints**: NULL values allowed where appropriate

### Lessons Learned
1. **Always have fallbacks**: Never rely solely on one cache mechanism
2. **Test on fresh installs**: Ensures plugin works for new users
3. **Document thoroughly**: Future issues easier to debug
4. **User verification is critical**: Real-world testing catches what unit tests miss
