## Critical Issues Encountered & Resolved

### Issue #1: PHP Version Incompatibility
**Error:** `Composer detected issues in your platform: Your Composer dependencies require a PHP version ">= 8.3.0"`

**Root Cause:** PhpSpreadsheet v5.2.0 requires PHP 8.3+, Docker container runs PHP 8.2.17

**Resolution:**
```bash
composer require "phpoffice/phpspreadsheet:^2.0" --update-with-dependencies
composer install --no-dev --optimize-autoloader
```
- Downgraded to PhpSpreadsheet 2.4.1
- Verified compatibility with PHP 8.2.17
- All features still available in 2.x branch

---

### Issue #2: ReportsController File Corruption (CRITICAL)
**Error:** All API endpoints returned no route, WordPress site failed to load analytics

**Root Cause:**
- Attempted to use `sed` command in Docker to replace `error_response()` calls
- Command incorrectly cleared the file to 0 bytes
- Both local and Docker copies corrupted

**Resolution:**
1. Recreated entire ReportsController.php from scratch (476 lines)
2. Replaced all `$this->error_response()` calls with proper `WP_Error()` returns
3. Validated PHP syntax
4. Copied to Docker and restarted container

**Files Affected:**
- `/ma-deal-room/src/REST/Controllers/ReportsController.php` - Fully recreated

---

### Issue #3: Missing error_response() Method
**Error:** `Call to undefined method MADealRoom\REST\Controllers\ReportsController::log_event()`

**Root Cause:**
- ReportsController was calling `$this->error_response()` which doesn't exist in BaseController
- Should use `WP_Error()` directly

**Resolution:**
- Replaced all 6 occurrences of `$this->error_response(...)` with:
```php
return new WP_Error(
    'error_code',
    'Error message',
    ['status' => 400]
);
```

---

### Issue #4: Missing log_event() Method
**Error:** `Call to undefined method MADealRoom\REST\Controllers\ReportsController::log_event()`

**Root Cause:**
- Code was calling `$this->log_event()` which doesn't exist in BaseController
- Logging calls were causing exceptions on every export attempt

**Resolution:**
- Removed all 3 `log_event()` calls from ReportsController
- Used `sed` to strip logging code cleanly:
```bash
sed -i '/^\t\t\t$this->log_event/,/^\t\t\t]);$/d' ReportsController.php
sed -i '/Log the.*event/d' ReportsController.php
```

### Issue #5: mPDF Temp Directory Not Writable
**Error:** `Temporary files directory "/var/www/html/wp-content/plugins/ma-deal-room/vendor/mpdf/mpdf/src/Config/../../tmp/mpdf" is not writable`

**Root Cause:**
- mPDF default temp directory in vendor/ not writable
- Docker container permissions issue

**Resolution:**
1. Created custom temp directory: `/ma-deal-room/tmp/mpdf`
2. Updated PDFReportGenerator to use custom directory:
```php
private function generatePDF(string $html, string $title): string {
    $tmp_dir = WP_PLUGIN_DIR . '/ma-deal-room/tmp/mpdf';
    if (!is_dir($tmp_dir)) {
        wp_mkdir_p($tmp_dir);
    }

    $mpdf = new Mpdf([
        // ... other config ...
        'tempDir' => $tmp_dir,
    ]);
}
```
3. Set permissions: `chmod 777 /ma-deal-room/tmp`

### Issue #6: Template Data Structure Mismatch
**Error:** `Undefined array key "total_value"` in transaction-summary.php

**Root Cause:**
- Template expected `$by_status['total_transactions']` and `$by_status['total_value']`
- AnalyticsService returns different structure: `['total' => X, 'breakdown' => [...]]`

**Resolution:**
- Updated template to calculate totals from breakdown array:
```php
<?php
$total_transactions = $by_status['total'] ?? 0;
$total_value = 0;
foreach ($by_status['breakdown'] as $item) {
    $total_value += $item['total_value'] ?? 0;
}
?>
```

**File Modified:** `ma-deal-room/src/Templates/reports/transaction-summary.php`

### Issue #7: Frontend Response Validation
**Error:** Export button triggered download but nothing happened

**Root Cause:**
- Frontend wasn't checking for `response.success` property
- Empty responses passed validation

**Resolution:**
- Updated reportService.ts to validate response structure:
```typescript
if (!response || !response.success || !response.data) {
    throw new Error('Invalid response from server');

```

## Known Limitations

1. **Large Dataset Handling:** Current implementation loads all data into memory. For datasets > 10,000 rows, consider implementing:
   - Streaming exports with chunked database queries
   - Background job processing with download links
   - Progress indicators for long-running exports

2. **Excel Features:** Limited to basic formatting. Advanced features not implemented:
   - Charts/graphs
   - Conditional formatting
   - Multiple sheets
   - Formulas

3. **Browser Compatibility:** Download method works in modern browsers but may have issues in IE11

## Lessons Learned

1. **Always backup before destructive operations:** File corruption could have been avoided with git commit before sed operations
2. **Test in Docker environment:** PHP version mismatches can cause production issues
3. **Validate external dependencies:** Check PHP version compatibility before installing libraries
4. **Use proper error handling:** WP_Error vs custom error methods - stick to WordPress conventions
5. **Template data contracts:** Document expected data structure in templates to avoid runtime errors
6. **Route caching:** WordPress aggressively caches REST routes - always flush after changes
7. **Frontend validation:** Always validate API responses before processing
