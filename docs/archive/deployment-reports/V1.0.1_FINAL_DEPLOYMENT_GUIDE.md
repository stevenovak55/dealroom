## What's New in v1.0.1

### 1. Output Buffering Fix (CRITICAL)
**Problem:** Plugin generated 1,574 characters of unexpected output during activation, causing "headers already sent" warnings.

**Solution:**
- Added output buffering (`ob_start()` / `ob_end_clean()`) to activation function
- Wrapped all migrations in try-catch blocks
- Updated all error_log calls to only write to log files (not browser output)
- Changed logging to only occur when `WP_DEBUG_LOG` is enabled

**Impact:** Clean activation with no warnings or errors.

### 2. MLS Configuration Infrastructure
**New Files:**
- `src/Models/MLSConfig.php` - Model for MLS configuration data
- `src/Repositories/MLSConfigRepository.php` - Repository for database operations

**Changes:**
- Registered `mls_config_repository` in service container
- MLS configuration now saves successfully without errors

### 3. Automatic Task Definitions Sync
**Enhancement:** Plugin now syncs 276 task definitions from 7 YAML templates automatically during activation.

**Files synced:**

- Complete uninstall support (removes all data when deleted)

## Deployment to Live Site

### Prerequisites

1. **Backup first!** (Required)
   ```bash
   # Database backup
   wp db export backup-$(date +%Y%m%d-%H%M%S).sql

   # Plugin files backup
   tar -czf plugin-backup-$(date +%Y%m%d-%H%M%S).tar.gz wp-content/plugins/ma-deal-room/
   ```

2. **Download ZIP to your computer:**
   - Location: `/home/snova/projects/dealroom/ma-deal-room-v1.0.1.zip`
   - Size: 51.35 MB

### Deployment Method 1: WordPress Admin (Recommended)

**Step 1:** Log into WordPress Admin on live site

**Step 2:** Go to **Plugins > Add New**

**Step 3:** Click **Upload Plugin** button (top of page)

**Step 4:** Select `ma-deal-room-v1.0.1.zip` from your Downloads folder

**Step 5:** Click **Install Now**

**Step 6:** When prompted, click **"Replace current with uploaded"**

**Step 7:** After upload completes:
1. Go to **Plugins > Installed Plugins**
2. Find **MA Deal Room**
3. Click **Deactivate**
4. Click **Activate**

**Why deactivate/reactivate?**
- This runs the activation hook which:
  - ✅ Runs new database migrations
  - ✅ Syncs 276 task definitions
  - ✅ Registers new services
  - ✅ Updates version number

### Deployment Method 2: FTP/SFTP

**Use this if:**
- Upload limit is too small (< 64 MB)
- WordPress upload is timing out

**Steps:**

1. **Extract ZIP** on your local computer

2. **Connect via FTP/SFTP** to live site

3. **Navigate to:** `wp-content/plugins/`

4. **Rename existing folder:**
   - Rename: `ma-deal-room` → `ma-deal-room-backup-20251103`

5. **Upload new folder:**
   - Upload the extracted `ma-deal-room` folder
   - This will take several minutes (4,708 files)

6. **Set permissions:**
   - Folders: 755
   - Files: 644

7. **Activate in WordPress Admin:**
   1. Go to **Plugins > Installed Plugins**
   2. Click **Activate** on MA Deal Room
   3. Verify no errors appear

### Deployment Method 3: SSH/Command Line

**For advanced users:**

```bash
# Upload ZIP to server
scp ma-deal-room-v1.0.1.zip user@server:/tmp/

# SSH into server
ssh user@server

# Navigate to WordPress root
cd /path/to/wordpress

# Backup current plugin
mv wp-content/plugins/ma-deal-room wp-content/plugins/ma-deal-room-backup-$(date +%Y%m%d)

# Extract new plugin
unzip /tmp/ma-deal-room-v1.0.1.zip -d wp-content/plugins/

# Set permissions
chown -R www-data:www-data wp-content/plugins/ma-deal-room
find wp-content/plugins/ma-deal-room -type d -exec chmod 755 {} \;
find wp-content/plugins/ma-deal-room -type f -exec chmod 644 {} \;

# Deactivate and reactivate
wp plugin deactivate ma-deal-room
wp plugin activate ma-deal-room
```

## Troubleshooting

### Issue: "Upload failed - File size exceeds limit"

**Cause:** PHP upload limit too small

**Solution A:** Increase limits in `wp-config.php`:

```php
// Add before "That's all, stop editing"
@ini_set('upload_max_filesize', '64M');
@ini_set('post_max_size', '64M');
@ini_set('memory_limit', '256M');
@ini_set('max_execution_time', '300');
```

**Solution B:** Use FTP/SFTP method instead

---

### Issue: Still getting "Failed to create configuration"

**Possible causes:**

1. **Plugin files didn't upload correctly**
   - Via FTP, verify this file exists: `wp-content/plugins/ma-deal-room/src/Repositories/MLSConfigRepository.php`
   - Check file modification date (should be today)

2. **Plugin not activated after upload**
   - Must deactivate and reactivate for activation hook to run

3. **PHP cache (opcache) not cleared**
   ```bash
   # Restart PHP-FPM to clear cache
   sudo service php8.1-fpm restart
   # OR
   sudo service php-fpm restart
   ```

4. **WordPress cache not cleared**
   ```bash
   # Via WP-CLI
   wp cache flush

   # Or delete cache directory
   rm -rf wp-content/cache/*
   ```

5. **Old plugin code still in memory**
   - Log out of WordPress admin
   - Clear browser cache (Ctrl+Shift+Del)
   - Log back in

---

### Issue: Task definitions count = 0

**Cause:** Activation hook didn't run

**Solution:**

1. Deactivate plugin
2. Activate plugin (runs activation hook)

**Or manually trigger:**

```bash
# Via WP-CLI
wp eval 'ma_deal_room_sync_task_definitions();'
```

---

### Issue: 403 Errors still appearing

**Cause:** Browser cache or old JavaScript

**Solution:**

1. Hard refresh browser: **Ctrl+Shift+R** (Windows) or **Cmd+Shift+R** (Mac)
2. Clear browser cache completely
3. Log out and log back in to WordPress

---

### Issue: "Class not found" errors

**Cause:** PHP autoloader cache

**Solution:**

```bash
# Regenerate Composer autoload
cd wp-content/plugins/ma-deal-room
composer dump-autoload -o

# Restart PHP-FPM
sudo service php-fpm restart
```

---

### Issue: "Headers already sent" warning

**Cause:** Should be fixed in v1.0.1, but if you still see it:

**Debug:**

1. Enable debug logging in `wp-config.php`:
   ```php
   define('WP_DEBUG', true);
   define('WP_DEBUG_LOG', true);
   define('WP_DEBUG_DISPLAY', false);
   ```

2. Check debug log:
   ```bash
   tail -100 wp-content/debug.log
   ```

3. Look for output happening before headers are sent
